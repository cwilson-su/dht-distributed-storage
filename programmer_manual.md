# PROGRAMMER MANUAL

## 1. PROJECT STANDARDS AND CONVENTIONS

### 1.1. File Encoding and Character Set

**CRITICAL:** The LaTeX build environment for this project is strictly configured for **ASCII** encoding.

* **Do NOT use UTF-8 characters.** The use of direct accented characters (é, à, ç, œ, etc.) or special symbols will cause fatal compilation errors (e.g., "Invalid UTF-8 byte sequence" or "Emergency stop").
* **Use LaTeX Escapes:** You must use standard LaTeX commands for special characters.
* Instead of `é`, use `\'e`
* Instead of `è`, use `\`e`
* Instead of `ç`, use `\c{c}`
* Instead of `œ`, use `\oe`
* Instead of `ê`, use `\^e`


### 1.2. Naming Conventions

The project follows an iterative development structure. Source code packages and LaTeX sections should adhere to the following versioning scheme:

* **dht0**: Refers to the initial, naive implementation (basic node structure, no routing logic).
* **dht1**: Refers to the first functional iteration (introduction of Origin tracking, Hops counting, etc).
* **dht2**: (Future) Refers to the stabilized version with TTL and response handling.


## 2. VERSION CONTROL AND REPOSITORY MANAGEMENT

To maintain a clean repository and avoid conflicts between different local environments (e.g., Windows vs. Mac, different Eclipse versions), we follow a strict "Source Only" policy.

### 2.1. Git Ignore Policy

We do **not** commit compiled binaries or IDE-specific configuration files. The repository is configured to ignore the following:

* **`.class` files:** These are generated by the Java compiler and should never be tracked.
* **`bin/` directory:** The default output folder for Eclipse builds.
* **`.metadata/` folder:** Contains local Eclipse workspace preferences.
* **`.log` files:** LaTeX compilation logs.

### 2.2. Java Source Code Management

When pushing changes from Eclipse:

1. **Only commit the `src/` folder.** This contains the actual `.java` files.
2. Do **not** commit the entire Eclipse Workspace.
3. If you add external libraries (`.jar`), place them in a `lib/` folder and commit that folder, but do not commit the absolute paths in `.classpath`.

## 3. FIGURE INTEGRATION WORKFLOW

We utilise `draw.io` for all vector graphics to ensure high quality in the PDF report. To maintain consistency, please follow this strict procedure for creating and importing figures.

### Phase 1: Creation

1. Open **draw.io** (desktop or web version).
2. Create your diagram. Ensure you use a white background (not transparent) for better visibility in the report.
3. Save the source file (`.drawio` or `.xml`) directly into the project's `figures/` directory.

### Phase 2: Export and Conversion

We do not export images manually to PNG or JPG. We use a conversion script to generate high-quality PDFs that LaTeX can digest.

1. Navigate to the `figures/` folder in your terminal or file explorer.
2. Locate the conversion script  `convert_drawio_figures.sh` provided in this folder.
3. **Execute the script.**
* The script will automatically detect updated `.drawio` files.
* It will generate a corresponding `.pdf` file for each diagram (e.g., `NodeThread.drawio` -> `NodeThread.drawio.pdf`).
* *Note: This approach is based on the method described at: [https://tex.stackexchange.com/questions/427622/importing-diagram-from-draw-io-into-latex*](https://tex.stackexchange.com/questions/427622/importing-diagram-from-draw-io-into-latex)


### Phase 3: Inclusion in LaTeX

Once the PDF is generated in the figures folder, include it in your `.tex` file using the standard `figure` environment. Always use the `[H]` float specifier to prevent the image from drifting.

**Template:**

```latex
\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{figures/YourDiagramName.drawio.pdf}
    \caption{\textbf{Bold Title.} Description of the figure using ASCII characters.}
    \label{fig:unique_label_name}
\end{figure}

```

## 4. LaTeX COMPILATION AND TROUBLESHOOTING

We are using a local copy of LaTeX. Below are common issues and solutions.

### 4.1. "Invalid UTF-8 byte sequence"
* **Cause:** You copied text containing an accented character (like 'é') or a special quote symbol directly into the editor, and the editor saved it in Windows-1252/ANSI format while LaTeX expects ASCII/UTF-8 commands.
* **Solution:** Find the offending character (often in a comment or a recently added paragraph) and replace it with the LaTeX code equivalent (see Section 1.1).

### 4.2. "Incomplete \iffalse" or "Runaway argument"
* **Cause:** This is often a cascading error caused by the Encoding issue above. When LaTeX crashes on a bad character, it loses track of the document structure (end of figures, end of environments).
* **Solution:** Do not look for a missing brace `}`. Fix the encoding error first, and this error will usually disappear.

### 4.3. Figures not updating
* **Cause:** You modified the `.drawio` file but forgot to run the conversion script.
* **Solution:** LaTeX includes the `.pdf`, not the `.drawio` source. You must run the script in the `figures/` folder to regenerate the PDF after every modification.

### 3.4 "I can't write on file..." or "Permission Denied"
* **Cause:** You are trying to compile the LaTeX document while the previous version of the PDF is still open in your PDF viewer (Adobe Reader, etc.). Windows, for instance, locks the file, preventing the compiler from overwriting it.
* **Solution:** Close the PDF viewer before hitting "Build" or "Compile." (Some lightweight viewers like SumatraPDF do not lock files and do not cause this error).

## 5. Automated UML Documentation

This project includes an automation suite to generate UML class diagrams directly from your Java source code. These diagrams are produced as PDFs, perfect for inclusion in technical reports or LaTeX documents.

#### Prerequisites

Before running the script, ensure your Linux environment has the following dependencies installed:

* **Java Runtime (JRE/JDK)**: Required to execute the PlantUML engine.
* **Python 3**: Used for the structural analysis and extraction of Java members.
* **Graphviz**: Essential for calculating relational layouts and arrows.
* **librsvg2-tools**: Provides the `rsvg-convert` utility to transform diagrams into PDFs.

#### Installation on Fedora
```bash
sudo dnf install java-latest-openjdk python3 graphviz librsvg2-tools

```

#### Installation on Ubuntu/Debian

```bash
sudo apt-get update
sudo apt-get install default-jre python3 graphviz librsvg2-bin

```

#### Configuration

The script `generate_all_diagrams.sh` contains two primary configuration variables at the top of the file:

1. **`PLANTUML_JAR`**: The absolute path to your `plantuml.jar` file.
* *Default*: `/usr/local/bin/plantuml/plantuml.jar`


2. **`ROOT_DIAGRAMS_DIR`**: The folder where the generated PDFs will be stored.
* *Default*: `diagrams`

#### Features of the Generated UML

The script performs a "Deep Parse" of your code to ensure academic-grade documentation:

* **Visibility Modifiers**: Automatically maps Java keywords to UML symbols: `+` (public), `-` (private), `#` (protected), and `~` (package-private).
* **Enum Extraction**: Fully documents internal structures, such as the `Type` enum in the `Message` class, including constants like `PUT` and `GET`.
* **Generic Relationships**: Dynamically detects and draws:
* **Implementation**: Dashed arrows (`..|>`) between `NodeThread` and the `Node` interface.
* **Association**: Solid arrows (`-->`) between classes based on field declarations.
* **Dependency**: Dashed arrows (`..>`) for method parameters.


* **Logic Filtering**: Strictly excludes method implementation details (e.g., `break`, `if` statements, or `System.out.println`) to keep the focus on architecture.


#### Workflow Recommendation

To ensure your documentation always reflects the current state of your architecture:

> **Please run the generation script whenever you modify the Java source code, specifically before performing a `git commit` or `git push`.**

#### Quick Command:

```bash
chmod +x generate_all_diagrams.sh
./generate_all_diagrams.sh

```
